## 10. 基本機能と応用機能の区別

- 公開APIの基本版は未認証利用を対象とする。
- Sanctum認証・所有者認可の追加は応用機能として扱う。
- 先行資料のMS10表記だけを理由に応用機能を必須化しない。
- 2FA等の応用機能は基本版の回帰検証と区別する。
- 並行競合・負荷試験は正式要件上の必要性を確認する。

## 11. 後続作業の共通完了判断

- 正式要件・PM回答・コーチ指摘と実装が整合している。
- 変更した仕様に対応するテストが存在する。
- 正常系・異常系・境界値・認証認可を必要に応じて検証する。
- 異常時に既存データや関連データを不正に変更しない。
- 全体回帰テストが成功する。
- 基本機能の行カバレッジ60%超を維持する。
- 変更理由・根拠・影響・資料反映先を記録する。

未承認事項や未検証事項を完了済みとして扱わない。
個別の照合、テスト設計のレビュー、Excel転記は継続管理する。
