## 出版日の保存・読取仕様

| 操作・入力 | Web・公開APIの処理 |
| --- | --- |
| 登録で出版日を省略 | ControllerがNULLを明示して保存 |
| 登録で空欄・空白・明示NULL | 既存ミドルウェアの正規化とnullable検証を通しNULLで保存 |
| 更新で出版日を省略 | 検証済み属性にキーを加えず、既存値を保持 |
| 更新で空欄・空白・明示NULL | キーとNULLを更新属性に残し、NULLへ変更 |
| 有効な年月日 | 従来のY-m-d形式で保存・返却 |
| 配列・不正型・不正日付 | 従来の入力エラーで拒否 |
| API一覧・詳細・登録更新応答 | 未登録はpublished_dateキーを含むJSON null |

- UpdateBookRequestはStoreBookRequestのルールを継承する。省略と明示NULLを区別するため、更新時に出版日のデフォルト値を補わない。
- description・image_urlは変更しない。Web更新で省略すると保持、API更新で省略すると既存どおりNULLとなる。
- ISBN必須・半角数字13桁・一意性、自身除外、タイトル・著者・ジャンル、登録者決定、所有者認可、ジャンル同期、トランザクション・競合処理は維持する。
- Bookのdateキャストは維持する。詳細BladeはNULL時「未登録」、編集フォームは空欄を表示できるためModel・Bladeは変更しない。

## Migrationの適用・復旧条件

- 新規Migration：2026_11_26_000000_make_books_published_date_nullable.php。過去のMigrationは変更しない。
- 既存MySQL環境のALTER TABLE MODIFY COLUMNでDATEのNULL許可だけを変更する。Doctrine DBAL等の追加依存や、Schema全体の動作設定変更は行わない。
- 使用する接続のGrammarでテーブル名を引用し、テーブル接頭辞を尊重する。既存の日付・他カラム・一意制約・外部キー・関連データは書き換えない。
- upは適用コードのみ作成し、今回実行しない。開発DBへの適用は、ユーザーが対象・未適用Migration・バックアップ・停止可能時間を確認する別段階とする。テスト用DBへの適用結果を開発DBへの適用済みと混同しない。
- downは出版日NULLの存在を確認し、残っていれば理由を示すRuntimeExceptionでALTER前に停止する。データ削除、架空日付の補完は行わない。
- NULLがない場合だけNOT NULLへ戻す。実環境の復旧では書き込みを停止し、正しい日付が確認できないレコードの扱いと対象Migrationを先に確認する。NULL解消を自動化したり、開発DBのrollback・初期化をテスト手順にしたりしない。
- MySQL DDLは暗黙COMMITを伴い、存在確認とDDLを通常のトランザクションで一体化できない。適用・復旧中の並行書き込みを避ける。元のアプリへ戻す前に、NULLを扱える状態と復旧可否を確認する。

### 既存期待値を変更した理由

- BookValidationTest、API StoreBookValidationTestの必須エラー対象から出版日だけを除外する。他の必須条件は維持。
- API BookWriteRequiredInputTestの出版日未送信POST・PUTの2拒否ケースを、新規テストの省略時成功・保持ケースへ置き換える。成功させるための条件緩和ではなく承認仕様への変更。
- IsbnLookupTestの保存連携内にある「空出版日を拒否」の入力を、存在しない2026-02-30へ変更して不正日付拒否を維持する。ISBN取得自体の日付不足エラーは変更しない。
- 既存の検索・ソート・ページ・効率テストは重複追加・期待値変更をしない。

### Migrationテストの隔離

- CreatesApplicationのtesting実接続先確認を維持し、専用接続でもmysql・testing・SELECT DATABASE()をDDL前に確認する。
- RefreshDatabaseのトランザクション内でDDLを実行しない。testing内のランダム接頭辞付き専用接続で、元のbooks・book_genres定義と必要な親テーブルだけを作る。通常の業務テーブルとmigrations履歴は変更しない。
- DATE列のNULL属性以外のメタデータ、既存行、キー・参照制約を比較する。NULLのdown拒否ではデータと構造の保持を確認し、隔離した当該テスト行だけを除去してNULLなしの復旧も確認する設計。
- finallyで専用テーブルを外部キー順に削除し、Schema・既定接続・接続設定を復元して専用接続を破棄する。他のMigrationやRefreshDatabaseStateへ変更を残さない。
- 以上はテストコードの設計。現時点で実行・安全性の実測確認済みとは扱わない。
