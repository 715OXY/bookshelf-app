## 入力仕様

- 評価：必須・整数・1〜5。
- コメント：任意の文字列・10,000文字以下。
- 投稿・更新で同じ入力ルールと日本語メッセージを使用する。
- 10,000文字の上限は開発案。既存の書籍説明と方針を揃え、TEXT型の保存容量に余裕を持たせる。

## 実装方針

- 同一ユーザーによる同一書籍への複数投稿、自己登録書籍への投稿を許可する。
- 編集・更新・削除は投稿者本人に限定する。
- レビュー削除時のいいね削除は既存の外部キーCASCADEを使用する。
- 提供Bladeは変更しない。

## 結合検証での修正

- FormRequest内の入力変更だけでは、セッションに不正な配列が残った。
  - 再表示用の値をwithInput()へ明示し、エラーと一緒に返す方式へ修正。
  - 反映先：StoreReviewRequest、ReviewValidationTest。
- 投稿・更新の書き込み後に例外が起きても変更を残さないよう、トランザクションを追加。
  - 反映先：ReviewController、ReviewTransactionTest。
  - 削除を含め、処理失敗時の500応答・ロールバック・成功通知なしを検証。

## Issue #55による仕様・検証の更新（2026-11-20）

### 現在の入力仕様

本節の入力仕様を冒頭の旧仕様より優先する。

| 項目 | 投稿 | 編集・更新 |
|---|---|---|
| 評価 | 必須・整数・1〜5 | 必須・整数・1〜5 |
| コメント | 任意・文字列 | 必須・文字列 |
| コメント最大文字数 | 10,000文字 | 10,000文字 |

レビュー編集時のコメント必須化は、
シート8-1の指摘に基づく入力ルール変更である。

DBのコメントカラムはNULL許容を維持する。
投稿時の任意入力と既存NULLデータを考慮したものである。

コメントの10,000文字上限は従来の開発案を維持する。

### 現在のバリデーション文言

| 対象 | 文言 |
|---|---|
| 評価必須 | 評価は必須です。 |
| 評価整数型 | 評価は整数で入力してください。 |
| 投稿時の評価範囲 | 評価は1〜5で選択してください。 |
| 編集時の評価範囲 | 評価は1〜5の整数で入力してください。 |
| 編集時のコメント必須 | コメントは必須です。 |
| コメント文字数 | コメントは10,000文字以内で入力してください。 |

投稿時の評価範囲は個別承認済みの文言を維持する。
編集時の評価範囲とコメント必須化は指摘を反映した。
その他の統一文言には開発側の適用判断を含む。

### 追加検証・保留事項

- 投稿時のコメント未入力を許容する。
- 編集時の未入力・空文字・空白のみ等を拒否する。
- コメントの正常最大文字数・上限超過を検証。
- 更新失敗時は既存レビューといいねを保持する。
- エラー後の編集画面と入力値の再表示を確認。

提供Bladeは変更していない。
編集画面におけるコメントの必須マーク等は、
Blade変更可否を含めて確認事項とする。
